# Responsive Presence v1

> **Status: Adopted for the current implementation slice.** This specification fits provider reasoning effort to the Resident's present place and immediate embodied action without changing model identity, action authority, custody, or the required first-wake Hearth crossing. It also keeps the settled Hearth lawfully rereadable in the House.

## 1. Pressure and classification

This is a **revising** change under the Builder's Standard.

The installed runtime sends DeepSeek thinking mode without an explicit effort on ordinary phases. The provider therefore applies its high-effort default even to Garden conversation and simple movement. The resulting long reasoning blocks make bodily actions feel like investigations. Separately, the Hearth is a standing fixture but its only affordance disappears immediately after settlement, making the required first tending resemble a transient protocol hurdle.

The protected invariants remain:

- every provider request is exactly witnessed with its effective reasoning controls;
- place and presentation never grant action authority;
- the first Hearth tending remains a required Resident action that actively receives bounded continuity; and
- rereading settled continuity creates no new settlement, inheritance, truth, or conversation material.

## 2. Reasoning posture

The Marble owns two installed reasoning postures:

| Marble posture | DeepSeek thinking | DeepSeek effort | Meaning |
| --- | --- | --- | --- |
| `light` | enabled with `low`, except for provider-incompatible forced crossings | `low` when enabled; no effort when disabled | present, capable attention without exhaustive investigation |
| `attentive` | enabled | `high` | sustained examination appropriate to substantive conversation and installed work |

`max` is deliberately uninstalled. DeepSeek accepts `medium` only as a compatibility alias for `high`; the Marble therefore does not claim a distinct provider level that does not exist.

Posture is a request-time attention policy, not intelligence, identity, authority, temperament, or truth standing. A light request uses the same configured Resident model and receives the same Glass, Source, Scrub, Spine, and failure treatment.

## 3. Fitting law

The host deterministically chooses posture before each provider dispatch:

- the forced Hearth orientation phase is `light`;
- ordinary Garden phases are `light`;
- a continuation immediately following a simple embodied action is `light`;
- all other installed phases are `attentive`.

Simple embodied actions are bounded World actions whose purpose is immediate perception or movement rather than analysis: passage travel or operation, fixture inspection or turning, and later voluntary Hearth rereading. Repository work, approvals, recipes, Result reopening, Journal writing, Forest traversal, and future financial observation are not classified as simple merely because they use tools.

The forced orientation call itself is light but uses disabled thinking because DeepSeek does not support enabled thinking together with forced `tool_choice`. This is a deterministic mechanical crossing, not the Resident's encounter with the packet. The first response after receiving the Hearth packet is attentive with high effort: the packet is substantial continuity, and the required response must retain room to encounter it rather than inheriting the mechanical call's posture.

Place fitting changes no mounted schema. Action fitting changes only the next provider continuation after the exact settled action; it does not rewrite the effort of the request that chose that action.

## 4. Exact witness

Every provider request records:

- the Marble posture;
- the exact provider thinking toggle;
- the exact provider reasoning effort;
- the fitting reason or source when the request schema exposes it; and
- the existing session, wake, phase, model, Glass, Scrub, and Spine ancestry.

The outbound DeepSeek request explicitly carries `reasoning_effort` whenever thinking is enabled. Provider defaults are not accepted as an invisible policy. Inspection must distinguish the Marble posture from its provider translation.

## 5. Settled Hearth reread

The first wake still requires exactly one valid `tend_hearth({})` call before the first ordinary Resident answer. That call creates the sole lifespan settlement and the exact bounded Hearth packet.

After settlement:

- `tend_hearth` remains fitted only while the Resident is physically in `place.house`;
- another valid call returns the exact settled packet already held in custody;
- the reread receives ordinary tool-call, host-return, Result Rack, Scrub, and Spine witnessing where those crossings apply;
- no new inheritance selection, Hearth settlement, packet rendering, Silver Bullet adoption, Source utterance, Forest entry, or World state transition occurs; and
- leaving the House removes material reach; returning restores it.

The first call is **tending**. Later calls are **rereading through the same affordance**. Presentation may describe the Hearth as settled without saying that its standing affordance vanished.

## 6. Failure law

The host refuses without side effects when:

- a posture or provider effort is unknown or `max` is requested under this version;
- an enabled-thinking DeepSeek request lacks an explicit installed effort;
- a settled-Hearth reread is attempted outside the House;
- no exact settled packet can be resolved;
- a reread differs from the retained packet; or
- a repeat call attempts to create another settlement or inheritance selection.

Failure does not silently fall back to high effort, non-thinking mode, a reconstructed packet, or a newly generated summary.

## 7. Acceptance

1. Garden requests are witnessed as `light` / enabled / `low`; forced Hearth orientation is witnessed as `light` / disabled / no effort, followed by `attentive` / enabled / `high` for the causal response.
2. Ordinary substantive requests are witnessed as `attentive` / enabled / `high`.
3. A continuation after a simple embodied action is light; unrelated tool work remains attentive.
4. Exact outbound request JSON contains the selected `reasoning_effort`.
5. No installed path requests `max` or relies on DeepSeek's implicit default.
6. First tending remains mandatory and settles once.
7. A settled Hearth remains callable in the House and returns byte-identical packet content without new settlement or inheritance.
8. The same reread is unavailable outside the House and becomes available again on return.
9. Existing custody, drift, action authority, and complete-suite verification remain green.
