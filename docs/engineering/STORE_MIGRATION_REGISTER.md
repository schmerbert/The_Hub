# Store Migration Register

> **Status: Active engineering register.** This document records the operational posture of persistent Hub stores. Exact schema and migration law remains in code and owning specifications.

## Migration law

- Startup may create a fresh configured store and perform explicitly supported startup-safe schema evolution.
- Startup must not silently bless drift, fabricate ancestry, rewrite append-only history, or perform an operator-gated migration.
- Destructive, ancestry-changing, security-sensitive, or legacy-boundary migrations require an explicit command or adopted crossing, backup expectations, verification, and truthful refusal.
- Creating a new protected copy does not dispose of old plaintext or obsolete backups.

### Spotlight live-read stores (2026-09-11)

- **Observations:** `src/places/hub/spotlight/observation-store.js` owns a fresh generation-1 SQLite store at `.runtime/spotlight/observations.sqlite` by default. It retains normalized identifier-free observations and append-only attempt/settlement evidence, verifies hashes and links on opening, and refuses unknown generations or drift. Existing Hub stores are unchanged. There is no automatic repair or historical backfill. `npm run spotlight:verify` opens read-only and verifies without networking. Preserve the database and any WAL using a SQLite-consistent backup or a copy after graceful shutdown. Restore that copy on failure; do not bless a damaged store. An interrupted unsettled request remains evidence and cannot automatically refetch under the same identity. This is local financial observation custody, not encrypted Vault storage.
- **Standalone OAuth:** `src/connectors/robinhood/` owns a separate Windows-current-user DPAPI credential file at `.runtime/spotlight/robinhood-auth.dpapi`. Explicit `npm run spotlight:connect` creates it; refresh updates it atomically. Unsupported encryption, corrupt files and missing authentication refuse live calls. No Codex credential migration is supported. Restoring ciphertext requires the same Windows security context; otherwise reconnect. Explicit disconnect removes only this connector's credential file and does not claim cryptographic erasure of backups or revoke the broker-side grant. No token file enters source control, observations, logs, or Resident attention.
